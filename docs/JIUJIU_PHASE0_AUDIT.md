## 关键冲突与待确认规则

1. **狼刀规则冲突**：当前 `tallyWolfTarget()` 取最高票，平票空刀；新总提示词与核心方案要求全体狼人目标一致才击杀。当前测试明确覆盖多数决。必须在规则表中记录迁移后同步调整引擎、前端提示、AI 和回归测试，不能只修改说明。
2. **人数和角色冲突**：后端校验与元数据、前端上限为 12；新目标为 13 人，9 张角色类型加警长职位。不能仅将最大人数改成 13 就声称标准局完成。
3. **核心设计版本差异**：参考文档描述控制台 v2，仓库已有联网引擎。复用职责，不强制重命名或回退到控制台开发。
4. **范围变更**：精简分工文档排除语音/表白墙，总提示词明确重新纳入。以新总目标排入后续阶段，不能从计划中删除。
5. **死亡事件与胜负**：现有仅两阵营，尚无情侣关系、独立情侣胜利或特殊死亡技能队列。需要先设计并确认统一死亡事件顺序。

以下细则仍属于待确认规则，暂不改动现有玩法：警长首轮选举时机、平票及重投规则；普通放逐平票；女巫自救限制；守卫连守；同守同救；猎人中毒能否开枪；白狼王触发时机与目标；跨阵营情侣胜利及爱神归属；殉情和死亡技能的先后顺序；警徽移交/撕毁与超时默认行为；掉线/退出在对局中的处理。

## 风险和工程限制

- `RoomController.detail` 对任意已登录用户返回已知房间码的房间详情；STOMP 房间主题目前只校验登录与目的地格式，不核对成员。私人房间与未来群组/媒体必须补服务端访问控制。
- `ChatService.send` 超长文本使用 Java UTF-16 `substring(0, 500)`，可能截断 Emoji 代理对。平台聊天需按完整 Unicode 字符边界限制，并回归组合 Emoji。
- 进行中的房间和 GameState 在单进程内存中。数据库持久化账号与战绩不等于能恢复对局；重启会中断房间，多实例不能直接共享状态。
- 上次新增匹配用一个 RoomService 锁串行化房间操作；在课程规模下可用，但不能据此声称经过容量测试。事务与内存状态的一致性还需在房间重构时审查。
- MySQL 初始 SQL 与 H2 增量脚本均存在，但尚无统一版本迁移目录。新增社交表前需建立增量迁移、保留现有 H2 文件库和 MySQL 数据。
- 现有 43 条浏览器手工用例仍未完整填写执行记录。测试全绿不代表新平台全部功能完成。
- 默认开发密钥/数据库示例密码、公网健康检查信息、接口限流与上传边界需在公网阶段复核。配置与真实凭据分离，不向聊天索要密钥。

## 第一阶段的具体任务

第一阶段只涉及平台基础、账号与已有访问控制，不依赖狼人杀新规则或外部付费服务。

1. 建立可演进的数据库迁移目录与执行说明，为 users 增加可选签名/更新时间字段；先验证 H2 新库与旧库重复升级，保留现有数据。
2. 在现有 `auth`、`user` 模块增加本人修改密码能力：校验原密码、BCrypt 新密码、提高认证版本使旧会话失效；DTO 使用 `@Valid` 校验，禁止前端指定目标用户。
3. 新增个人中心页面和用户 API 封装，接真实数据；读取与修改昵称、签名、头像 URL，显示账号信息及战绩。图片上传留给媒体阶段，不能用无功能按钮冒充。
4. 建立啾啾品牌与导航基础，先提供真实可用的游戏和个人中心路由；聊天和表白墙在各自阶段完成后接入，不展示可点击却无业务的假入口。
5. 补齐房间详情与 STOMP 主题的成员权限策略，兼容公开列表的必要元信息；增加非成员访问、正常成员重连、私有队列隔离回归。
6. 同步 API、数据库、测试说明，执行已有测试与新增账号/权限集成测试、类型检查和构建。

预计涉及：现有 auth/user/config/websocket 模块、用户 DTO/entity、H2/MySQL 增量 SQL、前端 App/router/auth API、新个人中心视图与基础样式。第一阶段不修改特殊角色规则、不改变游戏引擎主体或数据表名称。

第一阶段验收：两个账号资料互不串号；修改密码必须验证原密码且旧登录失效；私人房间非成员不能读取或订阅；已有登录、匹配、四角色对局与身份隔离继续通过；迁移重复执行不丢数据。

## 外部依赖和后续决策

- 公网运行需要持续在线的服务器或主机与固定 HTTPS 入口；当前没有实际部署目标。该条件不阻塞本地平台业务开发。
- MySQL 集成与迁移演练需要可用 MySQL 实例；本地 H2 可用于开发和自动化测试。
- 实时语音需要 HTTPS/安全上下文、浏览器麦克风权限和可达的 STUN/TURN；仅在局域网成功不代表异地语音可用。
- 外部 LLM 真实验证需要服务端配置可用 Provider/Key；现有规则兜底可继续保持可测。
- 特殊狼人杀规则先形成独立规则表并确认，随后实施阶段 6。
- 原 Git 仓库/远端地址尚缺；后续应保留真实历史并建立版本管理，不反向伪造六人协作记录。
